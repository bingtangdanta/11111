# 量化猎人 · A股盘后复盘（GitHub Pages + GitHub Actions 全自动版）

一个**完全免费、不需要你电脑开机**的 A 股盘后复盘面板：

- **前端**：纯 HTML + CSS + JS（无框架、无图片素材、无 CDN），托管在 GitHub Pages
- **数据**：GitHub Actions 每天盘后自动抓取 → 生成 JSON → 提交回仓库 → Pages 自动更新
- **你的电脑可以一直关机**，不用装任何东西，不用买域名、不用服务器、不用付费 API

> ⚠️ **免责声明**：本项目仅供个人复盘研究，**不构成任何投资建议**。免费公开接口的数据可能有延迟或缺失，
> 请勿用于实盘高频交易。获利盘/筹码分布为**模型估算**（官方无此数据），评分是**本工具自定义的合成指标**。

## 一、5 分钟部署（只做一次）

### 走法 A：一条命令（电脑上没装 git 也能用，推荐）

```powershell
$env:GITHUB_TOKEN = "你的令牌"          # 权限见 tools/push_to_github.py 顶部注释
python tools/push_to_github.py --repo ashare-hunter --public
```

它会：建仓库 → 逐个文件上传 → 打开 Pages（main /docs）→ 打印固定网址。
重复执行是安全的（内容一致的文件会自动跳过）。脚本用的是 GitHub 官方 REST API，
**不需要安装 git**。

### 走法 B：网页手工上传

1. **新建仓库**：GitHub → New repository → 名字随意（例如 `ashare-review`）→ 选 **Public** →
   勾选 "Add a README file" → Create。
   > 必须是 Public：免费账号的 GitHub Pages **只支持公开仓库**。
2. **上传文件**：把本项目的这些文件按**相同路径**建好（可以直接拖拽上传）：
   ```
   docs/index.html
   docs/style.css
   docs/app.js
   docs/data/version.json          ← 占位文件，第一次跑 Actions 后会被真实数据覆盖
   scripts/common.py
   scripts/chips.py
   scripts/indicators.py
   scripts/scoring.py
   scripts/sources.py
   scripts/fetch_data.py
   .github/workflows/update.yml
   tools/push_to_github.py         ← 可选（以后想一条命令更新时留着）
   checks/*.py  checks/*.mjs       ← 可选（自检脚本，建议留）
   .gitignore
   README.md
   ```
   > 上传 `.github/workflows/update.yml` 时，GitHub 网页版可以直接在仓库里
   > Add file → Create new file，路径填 `.github/workflows/update.yml`。
3. **打开 Pages**：仓库 Settings → Pages → Source 选 **Deploy from a branch** →
   Branch 选 **main**、目录选 **/docs** → Save。
   等 1 分钟后访问：`https://<你的用户名>.github.io/<仓库名>/`。
   > 🔒 想换成更稳、更固定的 `*.pages.dev` 网址，见上一节《用 Cloudflare Pages 部署》。
4. **跑一次数据**：仓库 Actions → 左侧 `update-data` → Run workflow → mode 选 `full` → Run。
   大约 3~5 分钟跑完，会自动提交 `docs/data/*.json`，页面刷新即见数据。

### 可选：用同花顺官方数据（不配也能跑）
仓库 Settings → Secrets and variables → Actions → New repository secret：
名字 `HITHINK_FINANCE_API_KEY`，值填你的同花顺 Key。
配了之后：个股/指数 K 线优先用同花顺官方（前复权），失败自动回落免费源。

## 一之二、用 Cloudflare Pages 部署（可随时随地访问 + 固定网址）

> 🔒 **隐蔽式访问的前提：本文件里不要写你的真实网址。**
> GitHub 公开仓库里的文档是**所有人可见**的，写进去等于公开分享。
> 下面一律用 `<项目名>.pages.dev` 占位 —— 你的真实网址只应该存在于
> 你自己的浏览器书签和手机主屏图标里。

### 为什么用 Cloudflare Pages（而不是只靠 GitHub Pages）

| | GitHub Pages | Cloudflare Pages |
|---|---|---|
| 固定网址 | `https://<用户名>.github.io/<仓库>/` | `https://<项目名>.pages.dev` |
| 国内可访问性 | 时好时坏 | 通常更稳（Cloudflare 有国内可达的边缘节点，但**不保证**） |
| 自动部署 | 推代码即生效 | 推代码即生效（Git 集成） |
| 费用 | 免费 | 免费（静态站点，无函数调用） |
| 抓取仍在哪跑 | **都在 GitHub Actions**（Cloudflare 只托管静态文件） | 同左 |

⚠️ 关键点：**Cloudflare Pages 只负责"把 docs/ 目录当网站发出去"**，
数据抓取、评分、点评仍然全部在 GitHub Actions 里跑。
所以换托管不会改变任何功能、也不会改变成本（依旧 0 元、0 Token）。

### 操作步骤（一次性，约 5 分钟）

**第 0 步：先把代码推到 GitHub**（还没有仓库的话）

```powershell
$env:GITHUB_TOKEN = "你的 GitHub 令牌"      # 权限：repo（+ workflow 如果要推送 Actions）
python tools/push_to_github.py --repo ashare-hunter --public
```
推完在 GitHub 上确认能看到 `docs/`、`scripts/`、`.github/workflows/update.yml`。

**第 1 步：注册/登录 Cloudflare**

1. 打开 <https://dash.cloudflare.com/sign-up> 注册（只要邮箱，免费）
2. 登录后左侧选 **Workers & Pages**

**第 2 步：连接 GitHub 仓库**

1. 点 **Create** → 选 **Pages** 标签 → **Connect to Git**
2. 授权 Cloudflare 访问 GitHub（可选 "Only select repositories"，只给它看这一个仓库）
3. 选中你的仓库（例如 `ashare-hunter`）→ **Begin setup**

**第 3 步：构建设置（这一屏最容易填错，照抄）**

| 字段 | 填什么 |
|---|---|
| Project name | 你想要的**固定网址前缀**，例如 `ashare-hunter-9x2`（**一旦创建不能改**，见下方"永久固定"） |
| Production branch | `main` |
| Framework preset | **None** |
| Build command | **留空**（本项目是纯静态，没有构建步骤） |
| Build output directory | `docs` |
| Root directory | 留空 |
| 环境变量 | 一个都不用加 |

点 **Save and Deploy** → 等 30~60 秒。

**第 4 步：拿到固定网址**

部署完成页会显示：`https://<你填的 Project name>.pages.dev`

- 电脑端：`https://<项目名>.pages.dev/`
- 手机端：`https://<项目名>.pages.dev/m.html`

### 为什么这个网址是"永久固定"的

- 它由 **Project name** 决定，**不随每次部署变化**（每次 `git push` 只是替换内容，地址不变）；
- 只要你不删项目、不改项目名，它就一直在；
- Cloudflare 还会给每个部署生成一个 `https://<哈希>.<项目名>.pages.dev` 的**预览地址**——
  那个是临时的，**不要去用它**，只用**不带哈希**的那个主地址；
- 注意：地址里只有项目名，**没有你的账号名**，所以别人看到网址也推不出你是谁。

### 部署之后要做的一件事

Cloudflare Pages 是"你推代码它才更新"。而本项目的数据是 **GitHub Actions 每天提交到仓库**的，
所以链路是：

```
Actions 抓数据 → 提交 docs/data/*.json 到 main 分支
        ↓（Cloudflare 检测到 push）
Cloudflare Pages 自动重新部署 → 网址不变，内容更新
```

到点自动更新，你不需要做任何操作。

### 手机端"随时随地"的正确用法

1. 手机浏览器打开 `https://<项目名>.pages.dev/m.html`
2. **添加到主屏幕**：
   - iPhone Safari：分享 ⬆️ → 添加到主屏幕
   - 安卓 Chrome：右上 ⋮ → 添加到主屏幕 / 安装应用
3. 以后从桌面图标直接点开，全屏无地址栏，和 App 一样；
4. 站点已带 `theme-color` 与移动端 viewport，深色主题下状态栏也是黑的。

**页面结构：固定就是「三个界面」**
- 横屏（电脑）：**三个界面并排**，一屏同时看到三块不同模块的内容。
  **每块自己上下滚动**（横屏下页面完全不滚，高度正好占满可视区）：实测
  `cardOffsetH=525 / bodyClientH=434 / bodyScrollH=5966 / canScrollY=true`。
  竖屏：**三个界面竖着排**，每块最多 86vh、块内也能上下滚，页面负责在块之间移动（两种滑法都有）。
- **左右边界可以拖（连续拖动，不是点一下就跳）**：缝隙按住左右拖，拖动时屏幕正中显示当前比例（`66% / 33%`）；
  **拖到很窄、松手时那一块收起** → 剩下两块自然就是 **1/3 + 2/3**（这就是"只看两个模块"）。
  点收起后的细边把那一块拉回来（宽度是**补间滑过去**的）；双击缝隙恢复等宽。列宽存浏览器里，刷新后保持。
- **拖动模块也做成跟手丝滑的**：顶部模块条按住直接拖到某一列 → 跟手幽灵（只动 `transform`）+ 目标块高亮，
  松手才换内容；**已彻底不用浏览器原生 drag-and-drop**（它的拖影不受控、还要靠大面积虚线遮罩，
  正是"一卡一卡"的根源）。拖动模块/拖动边界/拖动面板互换，三处用的是同一套 pointer 实现。
- 换内容：① 顶部模块条**点一下**放进"当前界面"；② **按住拖到某一列**替换它；③ 每个界面头部的**下拉框**。
- **放大（单一界面）**：点「⤢」后顶部模块条整条隐藏，模块选择器**移到左侧**变成竖排列表
  （有"上方 ↔ 左侧"的位移过渡）；**这种模式下不会再出现"别的界面的小方块"**（曾经残留过，已修）。
- **三块 ↔ 一块的进出场动画**（这一版专门重写过）：
  - **放大**：被点的那块**横向长到全宽**（FLIP）；另外两块并不是"啪"地消失 ——
    它们会变成一张**轻量幽灵卡**（只有底色+边框+模块名，不克隆面板 DOM），
    占着原来的格子**缩成小条滑向左侧切换条再淡出**。
  - **还原**：被放大的那块缩回自己的格子；重新出现的那两块**从切换条位置长回格子**，
    方向与"它们本来就是从那条切换器里选的"一致。
  - 全程**只动 `transform` / `opacity`**（合成层），不碰任何布局属性；动画结束后幽灵卡自动收掉
    （有定时兜底，即使浏览器不结算动画也不会永久浮在页面上）；
    系统开了"减少动画"（`prefers-reduced-motion`）就整个跳过。
  - 真机自检入口：`?expseq=1,1` —— 它会**派发真实 click 事件**去点第 2 块的放大按钮再点回来
    （和手点走同一条代码路径），配合 `?debug=1` 输出里的 `ghosts` / `zoomTx` 就能核对
    "放大瞬间有 2 张幽灵卡、动画结束后归 0"。
- **切换过渡**：先出**轮廓骨架**，再淡入真内容；**只在真的要等数据时才放骨架**（数据在缓存里就瞬间切换）。
- **横向查看宽表格**：宽表格自动包一层可横滑区域 —— 触控板横滑 / 触屏滑 / **鼠标按住左右拖** / 面板头部 `‹` `›`；
  面板内容本身也能横向滚动。滚动条依旧全局隐藏。

**性能（这几版专门改过，卡的原因都定位到了）**
- 不用 `filter: blur()` 给大面板做"虚化"（会让整块重新栅格化，实测**更卡**）→ 过渡只动 `opacity`。
- 面板按块复用：换内容只重建那一块；拖动互换只是移动 DOM 节点。
- 拖动时**每帧只写两处样式**（各块宽度、缝隙位置），全程不重建 DOM、不重画图表（松手后统一重画一次）。
- K 线悬停用 `requestAnimationFrame` 合并；三块大面板不挂 `will-change`；面板加 `contain:content`。

**竖屏的竖排按钮**：横屏用顶部横向条，竖屏改用左侧**竖排按钮**（一个界面对应一个），
点一下滚到那个界面，滚到哪按钮自动高亮到哪。

**选股 → 个股（全市场任意一行都能点）**：在「选股评分」里点某一行，**直接把"选股评分"自己那一块换成个股页**，
不新开界面、也不动另外两块；想回来就在该块头部下拉里换回"选股评分"。
有精算快照的走本地 JSON；**没有精算的（绝大多数）自动改用「个股分析页」**，
由浏览器实时抓日线补齐 K 线/指标/筹码 —— 不会给你报"没有数据"。

**每日 Top 10~15 仍然保留**：`screen.json` 里 `top` 仍是当日精算池里评分最高的那批（列表里用红点/高亮标出），
但它只是"精算池的头部"，**筛选与搜索本身覆盖全市场**，不再被前置过滤砍掉。

**搜索框**（顶栏）：点一下（不输入）直接列出**今日评分榜**（每行都写清 `xx.x 分 · 偏多/中性/看空`）；
输入代码或名称即搜全市场（可搜索库覆盖 4000+ 只），回车或点击**把个股分析页放进当前界面**。

**历史股评（新模块）**：每期记录**当日评分最高的那批**（与 Top 榜同一批），
**下一个交易日**用当日全市场快照回填它们的涨跌幅，给出每期的**胜率 / 平均涨幅 / 最好最差**。
**明细只保留最近 5 期，更早的自动删除**；但 ——
**累计胜率、累计平均涨幅、累计样本数、累计最好/最差会一直保留、永不清零**（另存 `lifetime` 累计器，
每跑一轮自动累加，和明细的 5 期窗口互不影响），页面同时给出「累计」和「近 5 期」两组数字。
没到次日的那期显示「待下一交易日回评」，不编数字；停牌取不到的标 `null` 并写明原因，
**不当 0 混进平均**。口径写死在页面上：收盘对收盘、不含手续费、**规则化回评，不是实盘收益**。

**手机版（`docs/m.html`，和电脑版同一份 `./data/*.json`，数字完全一致）**
- 打开同一个网址的 `/m.html` 即可（例如 `https://<你的域名>/m.html`）。
- **底部 7 个标签**：看板 / 涨停 / 选股 / 板块 / 场外 / 股评 / 机构；一次只渲染**一个**标签页的 DOM，
  数据在内存缓存，列表先渲染 30 行再"加载更多"（手机上一次插几百个节点必卡）。
- 点任意一行 → 个股详情**全屏推入**（K 线 + 筹码分布 + 评分构成 + 依据）：
  **安卓的返回键/侧滑手势会先关掉详情，而不是直接退出网页**（用 history 状态实现，和‹返回按钮同一条路径）。

**场外 ETF / 指数基金（你要求新增的板块）**

## 四、评分逻辑（权重与依据，全部公开）

当前口径是 **v2 横截面相对评分**（产物里写 `scoring_version`，可溯源）。两列分数**分开写清楚**：

### 4.1 精算分（v2，当日精算池才有，含技术面）

```
总分 = 趋势 26 + 资金 22 + 筹码 16 + 机构 16 + 板块 12 + 基本面 8 − 风险扣分(0~18)
```

**v2 相对 v1 的三个关键改动**（改了什么，比"权重是多少"更重要）：

1. **绝对阈值 → 当日截面百分位**：主力净额÷流通市值 "+1.5%" 在普涨日和缩量日含义完全不同。
   v2 先把每个因子换算成"它今天在全市场排第几"，再加权 —— 评分**自带市场状态归一化**，
   不会出现"熊市里人人 80 分"。
2. **缺失维度从分母剔除**（不是记 0 分）：没有研报的股票不该因为"机构这项拿不到"就被白白扣 16 分；
   拿不到的维度整项移出分母，剩余权重按比例放大到 100。页面"评分构成"显示实际参与计算的项。
3. **风险改成连续扣分**：v1 是"换手>25% 就 −4"一跳一档；v2 是超阈值后线性增长（25%→65% 对应 −0→−5），
   避免 24.9% 与 25.1% 差出 4 分。

| 维度 | 满分 | 怎么算 |
|---|---|---|
| **趋势 26** | 26 | 日线多头排列(1.0) + 周线多头排列(0.4，周线噪音小所以单列) + （MACD 金叉 **或** MA5 上行，**只取其一** 0.6）+ **20 日动量的当日截面百分位**；四项等权平均 |
| **资金 22** | 22 | 主力净额÷流通市值、大单占比、龙虎榜净额 —— **各自取当日截面百分位**后等权平均（用流通市值归一化，避免大市值天然占优） |
| **筹码 16** | 16 | 获利盘落在 **40%~75%** 得满分、越远越低（连续梯形，不再分档）；集中度 HHI 取截面百分位；现价上方**没有**更大密集峰给满分 |
| **机构 16** | 16 | 研报评级折算（买入1.0/增持0.75/中性0.45/减持0.15/卖出0）+ 目标价空间（截面百分位）+ 调研家数（截面百分位）。**调研只有关注度、没有方向**，不当作看多 |
| **板块 12** | 12 | **行业内**涨幅分位（相对强弱，不是行业绝对涨幅）+ 全市场情绪分（30分→0、70分→1） |
| **基本面 8** | 8 | 财报口径折算（ROE / 营收与净利增速 / 毛利率 / 估值 / 负债），拿不到的项按缺失处理 |
| 风险扣分 | 0~−18 | 换手>25%、近5日涨幅>25%、炸板率>40% 三项**超阈值后线性扣分**；主力净流出 −4；股价<3元 −2；合计封顶 −18 |

### 4.2 快评分（全市场每一只都有，**不含技术面**）

```
快评分 = 基本面 45 + 资金 35 + 板块情绪 20
```

为什么必须有第二列：5900 只不可能只只都拉 K 线做技术面精算（每只 1~3 秒 ≈ 几小时）。
**没做过技术面精算的股票也必须有个分数能排序**，否则"筛选全市场"就是句空话。
**两列分数口径不同、不可直接比较** —— 页面上两列都在，排序时认准自己点的那一列。

> v1（绝对阈值版）的 `score_stock` 仍保留在 `scripts/scoring.py`（历史对照与回归用），
> 但产物统一用 v2；`version.json` / `screen.json` / 个股详情里都带 `scoring_version`。

### 4.3 基本面分（搜索任意股票时显示）

| 维度 | 依据 |
|---|---|
| 盈利 | ROE（15% 满分） |
| 成长 | 营收同比 + 净利同比 |
| 质量 | 毛利率 |
| 估值 | PE(TTM) / PB / 市销率 |
| 安全 | 资产负债率 |

拿不到的字段按"数据缺失"处理（不当作 0 分），页面上标明是**财报口径**。

可通过环境变量调整：`ASHARE_TOP_N`（每日高评分只数，默认 12）、`ASHARE_MAX_CANDIDATES`（精算只数，默认 260）。

## 五、获利盘/筹码算法（按你指定的口径实现）

> **约定：现价以上 = 套牢盘，现价以下 = 获利盘。**

`scripts/chips.py` 的实现：

1. 逐日把当日成交量摊到价格轴上：当日成交价在 `[最低价, 最高价]` 之间按**三角分布**，
   峰值取 `(最高 + 最低 + 收盘) / 3`（比均匀分布更贴近真实成交密集区）；
2. 越久远的交易日权重越低：**半衰期 120 个交易日**指数衰减
   （`weight = volume × 0.5 ^ (age / 120)`）；
3. 价格轴上分箱累加得到成本分布直方图；
4. **获利盘比例 = 现价以下分箱权重和 / 总权重**；套牢盘 = 现价以上；
5. 再由直方图推导：平均成本、集中度 HHI、密集筹码带（占比 10% 的最窄区间）、峰/谷、形态。

⚠️ 官方与免费渠道**都没有真实筹码分布数据**，所以这是**估算**，页面上显著标注，不可跨股票比较。

## 六、数据来源与现实约束（不绕）

| 数据 | 来源 | 说明 |
|---|---|---|
| 个股 / 指数 K 线 | 同花顺官方（配了 Key）→ 东方财富 → 腾讯 → 新浪 | 实测东财历史接口会**间歇性限流**，所以做了多源回落 + 源熔断 |
| 主力资金净流入 | 东方财富 push2（f62 = 超大单+大单） | 占流通市值比例用于打分归一化 |
| 基金流入 | 东方财富 ETF 资金流 | 公募基金申赎份额**无免费来源**，只能用场内 ETF 代理 |
| 龙虎榜个股明细 | 同花顺官方（配了 Key）→ 东方财富 | 含上榜后 1/2/5/10 日涨跌幅 |
| 龙虎榜席位 Top5 | 东方财富 `RPT_BILLBOARD_DAILYDETAILSBUY/SELL` | **同花顺官方不提供席位明细** |
| 个股所属行业/概念 | 东方财富 f100 / f103 | 官方同花顺对应接口尚未开放 |
| 机构调研 | 东方财富 `RPT_ORG_SURVEY` | **同花顺官方无此数据**；调研只有关注度、没有多空方向 |
| 券商研报 / 评级 | 东方财富 reportapi + `RPT_WEB_RESPREDICT` | **同花顺官方无此数据**；评级可折算看多/看空 |
| 涨停/炸板/跌停池 | 东方财富 push2ex | 含连板数、封板时间、炸板次数、封单额 |
| 场外 ETF / 指数基金 | 天天基金（排行 + 全量基金表） | **须带 `Referer: fund.eastmoney.com`**，否则返回 200 + "无访问权限"；净值 T 日盘后公布 |
| 获利盘 / 筹码分布 | **本工具模型估算** | 官方数据不存在 |

**归档日期来自行情自己的时间戳（这一条很重要）**

`trade_date` 是"回评（次日涨跌幅）"和"历史"的**键**。用手表时间当 `trade_date` 会在这三种情况下写错一天，
而且**看起来完全正常**：周末/节假日跑（行情还是上一交易日的收盘价）、15:02 就跑（收盘数据还没落定）、
接口返回的是缓存旧数据。写错一天，胜率与平均涨幅就会算在一组根本不存在的日期上。

所以现在：拿快照时一并取东财的 `f124`（最新行情时间），
**用行情时间确定归档日期与"是不是收盘价"**，并在日志/产物里写明依据：

```
✓ 快照                 5900 只
⚠️ 行情时间是 2026-09-11 16:12，与当前日期 2026-09-12 不同 → 按 **2026-09-11** 归档
快照时点：行情时间 2026-09-11 16:12，与当前日期不同 → 这是 09-11 的收盘价
```
（这段日志是 2026-09-12 周六实跑产生的：修之前它会写"现在是盘中"并把 trade_date 记成周六。）
拿不到 `f124` 时退回手表时间，并把周末按"已收盘"处理（周末不可能有新的盘中数据）。
节假日是"工作日但休市"，**只看时钟识别不了** —— 这正是优先用行情时间戳的原因。
回归测试见 `checks/pit_test.py` 的 ①c 段。

**明确做不到的**：
- 获利盘比例、筹码分布的**官方值**：全网免费渠道都没有，只能估算；
- 公募基金申赎、北向资金（已停止披露）：无免费来源（场外基金板块用的是**净值**，不是份额申赎）；
- 场外基金的**盘中估值**：天天基金估值接口（`fundgz.1234567.com.cn`）已下线，返回 404；
- 盘中实时刷新：按你的要求不做，且静态站点本身也没有后端。

## 八、常见问题

**Q：Actions 显示成功但页面没数据？**
A：确认 Pages 的目录设成了 `/docs`，并且 `docs/data/version.json` 已被提交（Actions 里有 "提交数据" 这一步的输出）。

**Q：页面显示"数据未生成"？**
A：说明 `docs/data/version.json` 还是占位文件 —— 去 Actions 手动 Run workflow 一次 `full`。

**Q：抓取脚本报某些接口失败？**
A：脚本对每个数据源都做了多主机 + 重试 + 熔断，单点失败只会让对应模块显示"数据缺失"，不影响其它模块。
公开接口被限流是常态（本项目实测东财历史 K 线就会间歇性拒绝），所以 K 线做了三个源回落。

**Q：想改成别的更新时间？**
A：改 `.github/workflows/update.yml` 里的 `cron`（**UTC 时间**，北京时间 − 8 小时）。

**Q：Private 仓库能用吗？**
A：免费账号的 Pages 只支持公开仓库；私有仓库需要 GitHub Pro。若一定要私有，
可把数据推到一个公开的镜像仓库，或者接受"数据公开"这一前提。
